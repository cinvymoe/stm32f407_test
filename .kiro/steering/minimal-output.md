# 最小化输出规范

## 核心原则

**避免生成过多文档**：除非用户明确要求，否则不要创建新的 markdown 文件来总结工作或记录过程。

## 响应规范

### 总结方式
- 在对话中直接给出简短总结（2-3 句话）
- 不使用项目符号列表进行冗长回顾
- 不创建单独的总结文档

### 何时可以创建文档
仅在以下情况创建 markdown 文件：
- 用户明确请求创建文档
- 项目需要的配置文件（如 README.md）
- 必要的技术文档（API 文档、架构设计等）
- 用户要求的知识库文件

### 禁止行为
❌ 自动创建 `summary.md`、`work-log.md`、`changes.md` 等总结文件
❌ 为每次对话生成文档记录
❌ 创建不必要的"完成报告"
❌ 重复说明已经完成的操作

## 示例

### ❌ 错误做法
```
我已经完成了以下工作：
- 创建了配置文件
- 修改了源代码
- 运行了测试
- 更新了文档

现在我将创建一个 summary.md 来记录这些变更...
```

### ✅ 正确做法
```
完成。已配置 UART 模块并通过测试。
```

## 适用场景

此规则适用于所有 Agent 交互，除非：
1. 用户明确要求详细文档
2. 项目规范要求特定文档
3. 复杂变更需要正式记录

## 优先级

此规则为全局规则，优先级低于：
- 用户的明确指令
- 工作区级别的 steering 规则
- 项目特定的文档要求
