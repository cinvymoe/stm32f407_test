# 代码归档助手

自动整理和归档 Agent 生成的文件，保持项目结构清晰有序。

## 功能说明

在每次 Agent 完成任务后，自动检查新创建或修改的文件，并根据文件类型归档到合适的目录。

## 归档规则

### 1. 示例代码
**目标目录**: `examples/`
**文件类型**:
- 包含 "example", "demo", "sample" 的文件
- 教程代码
- 概念验证代码

### 2. 测试文件
**目标目录**: `tests/`
**文件类型**:
- 单元测试
- 集成测试
- 测试数据文件

### 3. 文档文件
**目标目录**: `docs/`
**文件类型**:
- Markdown 文档（除了 README.md）
- API 文档
- 设计文档
- 教程文档

### 4. 配置文件
**目标目录**: `config/`
**文件类型**:
- 环境配置
- 应用配置
- 部署配置
- 非根目录的配置文件

### 5. 临时/实验文件
**目标目录**: `temp/` 或 `experiments/`
**文件类型**:
- 包含 "temp", "tmp", "test" 的文件
- 实验性代码
- 草稿文件
- 待整理的文件

### 6. 工具脚本
**目标目录**: `scripts/`
**文件类型**:
- 构建脚本
- 部署脚本
- 自动化脚本
- 辅助工具

## 不移动的文件

以下文件保持在原位置：
- 根目录的配置文件（Cargo.toml, package.json 等）
- README.md
- LICENSE
- .gitignore
- src/ 目录下的源代码
- .kiro/ 目录下的 Kiro 配置

## 归档流程

1. **检测阶段**: 识别新创建或修改的文件
2. **分类阶段**: 根据文件名、扩展名、内容判断类型
3. **移动阶段**: 将文件移动到对应目录
4. **更新阶段**: 更新相关引用和导入路径
5. **报告阶段**: 输出归档结果摘要

## 使用方法

### 自动模式（推荐）
Hook 会在每次 Agent 完成任务后自动运行，无需手动操作。

### 手动触发
在聊天中使用：
```
请使用 #code-archiver-guide 整理最近创建的文件
```

### 临时禁用
如果某次不需要归档，可以在任务开始前说明：
```
请创建示例文件，但不要归档（保持在当前目录）
```

## 配置选项

编辑 `.kiro/hooks/code-archiver.json` 可以自定义：

- **触发时机**: 修改 `when.type`
- **归档提示**: 修改 `then.prompt` 调整归档规则
- **启用/禁用**: 删除或重命名 hook 文件

## 目录结构示例

归档后的项目结构：

```
project/
├── src/              # 源代码（不移动）
├── examples/         # 示例代码
│   ├── basic.rs
│   └── advanced.rs
├── tests/            # 测试文件
│   ├── unit/
│   └── integration/
├── docs/             # 文档
│   ├── api.md
│   └── guide.md
├── config/           # 配置文件
│   ├── dev.toml
│   └── prod.toml
├── scripts/          # 工具脚本
│   ├── build.sh
│   └── deploy.sh
├── temp/             # 临时文件
│   └── experiment.rs
├── Cargo.toml        # 根配置（不移动）
└── README.md         # 项目说明（不移动）
```

## 智能特性

- **路径更新**: 自动更新移动文件后的导入路径
- **冲突处理**: 如果目标位置已有同名文件，会提示处理方式
- **批量操作**: 一次性处理多个文件
- **撤销支持**: 可以通过 git 撤销归档操作

## 最佳实践

1. **及时归档**: 让 hook 自动运行，保持项目整洁
2. **明确命名**: 使用清晰的文件名，便于自动分类
3. **定期检查**: 偶尔检查归档结果，确保分类正确
4. **自定义规则**: 根据项目特点调整归档规则

## 故障排除

**问题**: 文件被归档到错误的目录
**解决**: 手动移动文件，并在 prompt 中补充该类型的归档规则

**问题**: 某些文件不应该被移动
**解决**: 在文件名或路径中添加到"不移动"列表

**问题**: 归档后代码无法编译
**解决**: 检查导入路径是否正确更新，必要时手动修正

## 扩展建议

- 添加文件大小检查，大文件单独处理
- 集成 git 操作，自动提交归档变更
- 生成归档日志，记录所有移动操作
- 支持自定义归档规则配置文件
