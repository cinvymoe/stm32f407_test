# STM32F407 SD 卡 Bootloader 升级系统需求文档

## 1. 功能概述

实现基于 embassy-boot 的 STM32F407 bootloader 系统，支持从 SD 卡读取固件文件并进行安全升级，具备回滚机制。

## 2. 用户故事

### 2.1 固件升级流程
**作为** 设备用户  
**我想要** 通过 SD 卡升级设备固件  
**以便** 无需编程器即可更新设备功能

**验收标准：**
- 将固件 bin 文件放入 SD 卡根目录
- 按下指定按键启动升级流程
- 系统自动读取并烧写新固件
- 升级完成后自动重启进入新应用

### 2.2 升级安全保障
**作为** 系统开发者  
**我想要** 确保升级过程的安全性  
**以便** 避免因升级失败导致设备变砖

**验收标准：**
- 升级前验证固件完整性（CRC32 校验）
- 使用双分区方案（A/B 分区）
- 升级失败时自动回滚到旧版本
- 记录升级状态和错误信息

### 2.3 状态指示
**作为** 设备用户  
**我想要** 了解升级进度和状态  
**以便** 知道何时可以安全操作设备

**验收标准：**
- LED 指示升级状态（读取中、烧写中、成功、失败）
- 通过 RTT 日志输出详细进度信息
- 升级完成后 LED 显示最终状态

## 3. 功能需求

### 3.1 硬件接口

#### 3.1.1 SD 卡接口
- 使用 SDIO 接口连接 SD 卡
- 支持 FAT32 文件系统
- 4-bit 数据总线模式
- 引脚配置：
  - PC8-PC11: SDIO_D0-D3
  - PC12: SDIO_CK
  - PD2: SDIO_CMD

#### 3.1.2 按键输入
- 使用 PE4 按键触发升级检测
- 上拉输入模式，低电平有效
- 20ms 软件消抖

#### 3.1.3 LED 状态指示
- PA7 (LED1): 升级状态指示
  - 快闪（200ms）：读取固件中
  - 慢闪（500ms）：烧写固件中
  - 常亮：升级成功
  - 快速闪烁（100ms）：升级失败
- PA6 (LED2): 心跳指示（bootloader 运行中）

### 3.2 Flash 分区方案

基于 STM32F407VG 的 1MB Flash，采用以下分区：

```
0x08000000 - 0x08010000 (64KB)   : Bootloader
0x08010000 - 0x08090000 (512KB)  : Application Slot A (Active)
0x08090000 - 0x08110000 (512KB)  : Application Slot B (Update)
0x08110000 - 0x08120000 (64KB)   : Boot State (embassy-boot 状态存储)
```

### 3.3 固件文件格式

#### 3.3.1 文件命名
- 固件文件名：`firmware.bin`
- 放置位置：SD 卡根目录
- 可选：`firmware.crc` 存储 CRC32 校验值

#### 3.3.2 固件结构
- 纯二进制格式（.bin）
- 包含向量表和应用代码
- 最大大小：512KB
- 起始地址：0x08010000（应用区）

### 3.4 升级流程

#### 3.4.1 启动检测
1. Bootloader 启动后检测 PE4 按键状态
2. 如果按键按下，进入升级模式
3. 如果按键未按下，检查应用有效性并跳转

#### 3.4.2 固件读取
1. 初始化 SDIO 接口
2. 挂载 FAT32 文件系统
3. 查找 `firmware.bin` 文件
4. 读取文件大小并验证（≤512KB）
5. 计算 CRC32 校验值

#### 3.4.3 固件烧写
1. 擦除目标分区（Slot B）
2. 分块读取并烧写固件（4KB 块）
3. 每块烧写后验证
4. 更新进度指示

#### 3.4.4 分区切换
1. 标记 Slot B 为待激活状态
2. 设置 embassy-boot 状态标志
3. 重启系统
4. Bootloader 验证 Slot B 并切换

#### 3.4.5 回滚机制
1. 应用启动后标记自身为有效
2. 如果应用未标记有效（启动失败），bootloader 回滚到 Slot A
3. 最多尝试 3 次启动新固件

### 3.5 错误处理

#### 3.5.1 SD 卡错误
- SD 卡未插入：LED 快速闪烁，跳转到应用
- 文件系统损坏：LED 快速闪烁，跳转到应用
- 文件不存在：跳转到应用

#### 3.5.2 固件错误
- 文件过大：LED 快速闪烁，跳转到应用
- CRC 校验失败：LED 快速闪烁，跳转到应用
- 烧写失败：LED 快速闪烁，回滚到旧版本

#### 3.5.3 超时保护
- SD 卡初始化超时：5 秒
- 文件读取超时：30 秒
- 烧写超时：60 秒

## 4. 非功能需求

### 4.1 性能要求
- 固件读取速度：≥100KB/s
- 固件烧写速度：≥50KB/s
- 完整升级时间：≤15 秒（512KB 固件）

### 4.2 可靠性要求
- 升级成功率：≥99%（正常条件下）
- 掉电保护：支持升级过程中断电恢复
- 回滚成功率：100%

### 4.3 兼容性要求
- 支持 embassy-boot 0.3.x
- 支持 SD 卡：SDHC（4GB-32GB）
- 文件系统：FAT32

### 4.4 可维护性要求
- 详细的 RTT 日志输出
- 错误代码清晰可追溯
- 代码模块化，易于扩展

## 5. 约束条件

### 5.1 硬件约束
- Flash 大小：1MB
- RAM 大小：128KB
- SD 卡接口：SDIO（不支持 SPI 模式）

### 5.2 软件约束
- 使用 embassy-boot 框架
- 使用 embassy-stm32 HAL
- 使用 embedded-sdmmc-rs 或 fatfs 库
- no_std 环境

### 5.3 时间约束
- Bootloader 启动时间：≤500ms
- 按键检测窗口：2 秒

## 6. 依赖项

### 6.1 Rust Crates
- `embassy-boot-stm32`: Bootloader 框架
- `embassy-stm32`: STM32 HAL
- `embedded-sdmmc-rs` 或 `fatfs`: FAT32 文件系统
- `crc`: CRC32 校验
- `defmt`: 日志系统

### 6.2 硬件依赖
- STM32F407VG 开发板
- Micro SD 卡模块（SDIO 接口）
- 按键（PE4）
- LED（PA6, PA7）

## 7. 验收测试场景

### 7.1 正常升级流程
1. 准备有效固件文件到 SD 卡
2. 插入 SD 卡
3. 按住 PE4 按键并重启设备
4. 观察 LED 状态变化
5. 验证新固件运行正常

### 7.2 CRC 校验失败
1. 准备损坏的固件文件
2. 执行升级流程
3. 验证系统拒绝升级并保持旧版本运行

### 7.3 掉电恢复
1. 升级过程中断电
2. 重新上电
3. 验证系统回滚到旧版本或继续升级

### 7.4 回滚测试
1. 升级到故意制作的错误固件（无限循环不标记有效）
2. 验证 bootloader 自动回滚到旧版本

### 7.5 无 SD 卡启动
1. 移除 SD 卡
2. 正常启动设备
3. 验证直接跳转到应用程序
